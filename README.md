# Atoms Demo — 用一句话生成一个能用的网页应用

> 写一句话 → 智能体边想边写 → 右侧直接跑起来 → 不满意就「改一版」，功能真的会长出来 → 一键把成品分享给别人。

这是一个**以纯前端为主**的生成式应用工作台。它自己不是一个静态原型：里面每一条生成链路都是真的（真的调模型、真的流式输出、真的把产物跑在沙箱里、真的能点、真的会存）。

整个应用不需要后端就能完整跑起来（数据在本地、分享靠链接、Key 由你自己带）。两个可选的例外都在「让访客零配置就用上真模型」这一件事上：一个是**站点托管的模型**（部署一个只做「转发 + 限流」的代理，见 §1 末节与 §3.5），另一个更省事也更粗放——**把 Key 直接打进前端包**（见 §3.6）。两条都不做，其余功能一个都不少。

---

## 0. 连安装都省了：双击这一个文件

仓库根目录的 **`forge-standalone.html`** 就是整个应用——**双击，用浏览器打开，直接用**。不需要服务器、不需要构建、不需要联网、不需要 API Key（默认走内置演示引擎）。发给别人也是一个附件的事。

```bash
npm run single       # 重新生成它：vite build → 内联 → 真浏览器从 file:// 打开并跑一遍主流程
```

它**不是另一个简化版**：内联进去的就是 `dist/` 里那份已经验证过的生产包，构建脚本会逐字节校验内联内容与产物完全一致，所以单文件版和部署版是同一条代码路径。部署之后线上也会多出 `/forge-standalone.html` 这个静态文件（workflow 里会构建它），可以直接下载。

> 这份 HTML 是**刻意提交进仓库**的交付物，不是漏写 `.gitignore` 的构建产物。源码改动后跑一次 `npm run single` 会重新生成它，跑完 `git status` 立刻能看出它有没有过期。

> 也正因为它是**被 git 跟踪**的文件，它**故意不含**本站内置模型的 Key（见 §3.6）：构建时如果发现产物里内联了形如密钥的字符串，`scripts/standalone.ts` 会打印一段警告并点名这个文件——提交它等于把 Key 写进公开仓库历史，而且是永久性的。所以那份 Key 只在**部署环境**注入，单文件版永远是干净的一份。

> 只想用它、不关心实现的，看 [使用说明.md](使用说明.md)：怎么打开、三步上手、怎么分享给别人、真模型怎么接。

## 1. 30 秒跑起来

```bash
npm install
npm run dev          # 打开 http://localhost:5173
```

**不需要任何 API Key**：默认走「内置演示引擎」，输入一句话就能看到完整流程跑通。

```bash
npm run verify       # 类型检查 + 479 项断言：264 离线冒烟 + 69 托管代理 + 91 托管模式前端 + 31 真浏览器 + 10 部署形态 + 14 单文件
npm run build        # 产出 dist/（纯静态，可直接丢到任意静态托管）
```

### 发布成一个公网链接

产物是**纯静态 + 相对路径 + hash 路由**，所以随便放哪儿都能跑，且不需要任何重写规则：

```bash
npm run build        # 然后把 dist/ 整个目录丢给任意静态托管即可
npm run preview      # 本地模拟线上形态（http://localhost:4173）
```

本仓库带了一个 `.github/workflows/deploy.yml`：推到 GitHub 后在仓库 **Settings → Pages** 把 Source 选成 **GitHub Actions**，之后每次 push 都会自动构建并更新线上地址（构建前会跑类型检查、离线冒烟和**两套托管代理测试**——代理是唯一碰密钥、也唯一会花钱的组件，它回归了宁可这次不发版）。这条路径不需要任何本地部署工具链。

代理和静态站不同域时（比如静态站在 Pages、代理在 Vercel），在仓库 **Settings → Variables** 里加一个 `VITE_HOSTED_BASE_URL` 指向代理地址即可，workflow 会把它传进构建。不配也不会错：前端会自动试同源的 `/api`，探不到就不把「托管模型」这个选项露出来。

### 想让访客零配置就用上真模型：再部署一个托管代理

静态站只能解决「页面能打开」，解决不了「访客手上没有 API Key」。所以仓库里还带了一个**平台无关的托管代理**（`server/hosted-core.mjs`，只用 Web 标准 API），由站点自己出钱替访客调用模型：

```bash
npm run hosted:dev   # 本地起代理（http://127.0.0.1:8787），npm run dev 会自动把 /api 代理到它
```

本地跑真模型：把 `.env.example` 复制成 `.env`（已被 `.gitignore` 忽略），填上 `UPSTREAM_API_KEY`。
`npm run hosted:dev` 会自己读仓库根目录的 `.env`，不用手动 export；没有 `.env` 时它照常启动，
只是 `/api/health` 会回 `ready:false`，前端就不会把「托管模型」这个选项露给你。

线上二选一（两个平台用的都是同一份 `hosted-core.mjs`）：

| 平台 | 怎么做 | 环境变量 |
| --- | --- | --- |
| **Vercel**（推荐，`vercel.json` 已配好） | 把仓库导入 Vercel 即可，`api/` 目录被自动识别成 Functions | 见下表 |
| **Cloudflare Workers** | `server/worker.mjs` 就是一个现成的 Worker 入口，`wrangler deploy` | 同一份 |

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `UPSTREAM_API_KEY` | ✅ | 你（站点方）的模型 Key，**只存在服务端**，浏览器里拿不到 |
| `UPSTREAM_BASE_URL` | 默认 DeepSeek | 任何 OpenAI 兼容地址；换供应商只改这里 |
| `UPSTREAM_MODEL` | 默认 `deepseek-chat` | 服务端强制使用的模型（前端传什么都不算） |
| `HOSTED_DAILY_PER_IP` | 默认 20 | 每个 IP 每天能免费用几次 |
| `HOSTED_DAILY_GLOBAL` | 默认 200 | **全体访客每天的总量 = 每天的账单上限** |
| `HOSTED_MAX_TOKENS` | 默认 8000 | 单次响应的 token 上限 |
| `HOSTED_ALLOWED_ORIGINS` | 默认 `*` | 想收紧就填你自己站点的域名 |

前端不需要任何配置：同一域名下会自动探到 `${origin}/api`；代理和静态站不同域时，构建时给静态站加一个 `VITE_HOSTED_BASE_URL`，或者访客在设置里手填代理地址（`hostedBase`）。

### 更省事的一条：把 Key 打进前端包（`VITE_STATION_*`）

不想为「让访客零配置」再部署一个服务端，还有一个做法：构建时把你的 Key 作为 `VITE_` 变量注入，它会**被静态内联进 JS 包**。访客打开页面就自动用上真模型，一个服务端都不需要。代价写得很直白——**这个 Key 是公开的**，谁都能在页面源码里翻出来（见 §3.6 的完整取舍）。

部署环境里加一个 Secret 就生效（**别**写进 `.env`、更别提交它，`.env` 是被忽略的，但本机构建产出的单文件版是被跟踪的）：

| 位置 | 名字 | 说明 |
| --- | --- | --- |
| Actions **Secrets** | `VITE_STATION_API_KEY` | 你的上游 Key。**不设就是关闭这个功能**，站上不会出现「本站内置模型」这一项 |
| Actions **Variables** | `VITE_STATION_BASE_URL` | 可选，默认 `https://api.deepseek.com/v1`（任何 OpenAI 兼容地址） |
| Actions **Variables** | `VITE_STATION_MODEL` | 可选，默认 `deepseek-chat` |

本机想临时复现一次（**只构建，不提交产物**）：

```bash
VITE_STATION_API_KEY=sk-xxx npm run dev      # 或 npm run build
```

想撤掉它：把那个 Secret 删掉（或清空）再重新构建一次，站上就退回「什么都不配置」的形态——代码里一处都不用改。

## 2. 五条可验证路径

| 路径 | 需要什么 | 能验证到什么 |
| --- | --- | --- |
| **A. 内置演示引擎**（默认） | 什么都不需要 | 完整流程：需求 → 步骤日志 → 流式产出 → 沙箱里可交互的成品 → 改一版 → 分享链接 |
| **B. 接自己的模型** | 一个 OpenAI 兼容的 Key（DeepSeek / Kimi / 硅基流动 / 智谱 / OpenRouter / 阿里云百炼 / OpenAI 任选） | 真模型真调用、真流式、真实 token 统计 |
| **C. 站点付费的托管模型** | 什么都不需要（站点方在服务端出钱，见 §1） | 和路径 B 完全同一条流水线，只是 Key 在服务端；访客零配置就能用到真模型，有每日上限 |
| **D. 站点内置的模型** | 什么都不需要（站点方把 Key 打进前端包，见 §3.6） | 同一条流水线，打开即用、不限次数；代价是这个 Key 对所有人可见 |
| **E. 打开别人的分享链接** | 什么都不需要 | 分享码完全放在 URL 片段里，不经过任何服务器 |

设置页里粘一个 Key 就能切到路径 B；点「测试连接」会真的打一次 `/chat/completions` 再告诉你通没通。C 和 D 都会在**首次打开时自动生效**（站点配了哪条就切哪条，访客从没手动选过引擎的前提下），C 会在首屏右上角显示「本站付费调用 · 你今天还剩 N 次」，D 显示「本站内置 deepseek-chat，无需配置」。

**两条同时配好时的优先级是 C > D**：托管代理有服务端强制的每日上限（账单是有界的），内置 Key 没有；能走有护栏的那条就先走有护栏的。反过来，如果代理哪天挂了或额度耗尽，访客会被挪到 D 而不是悄悄退回模板引擎——这也是把 D 留着的主要理由。

## 3. 实现思路与关键取舍

### 3.1 为什么要有「内置演示引擎」

评审点开链接时不可能先去申请一个 API Key。所以默认走一条**确定性模板引擎**：5 个真实可用的应用模板（贪吃蛇 / 番茄钟 / 记账本 / 待办清单 / 通用管理工作台），按关键词打分挑最合适的那个，再用 `intent.ts` 从需求里抽出标题、主色、明暗——让产物看起来确实是「为这句话定制的」。

**取舍**：模板产物必然不如真模型灵活，但它把「零配置也能看到完整链路」这件事做到了。演示引擎和真模型走的是**同一套下游管线**（同一套步骤日志、同一套沙箱预览、同一套自检修复、同一套版本管理），所以两条路径的可信度是对等的，不是「演示引擎是假的」。

### 3.2 「改一版」是这个产品的核心动作，它必须真的变

模板是确定性的——同一句需求跑两次会得到**字节级相同**的 HTML。点「改一版」拿到一模一样的产物，整个产品的说服力就没了。

于是有了 `src/lib/enhance.ts`：迭代时**不重新套模板，而是在上一版 HTML 上打增量的功能补丁**。

- 补丁写在**通用 DOM 层**（自动扫描页面里最像「一列数据」的那组节点），不依赖具体模板结构，所以对**模型生成的产物同样适用**；
- 于是「加个搜索框 / 导出 JSON / 画柱状图 / 暗色主题」这四个功能，无论在哪个产物上、无论什么需求里说，都能真的挂上去；
- 累积语义：**每一版都保留上一版注入的脚本块**，每个功能带一个 `window.__forge_feat_*` 开关，打开第 3 版时按 1→2→3 顺序回放，最终能力是叠加的，且重复迭代同一需求**不会挂上两个一模一样的按钮**；
- **识别不到就不硬凑**：页面里没有列表时，如实显示「页面里没识别到列表内容，列表类功能已跳过」，而不是放一个点了没反应的假按钮。

三个真实踩过的坑（都写进测试里防止复发）：

1. **判断「上一版是不是已经有这个能力」时，被自己的痕迹骗了**——工具条按钮上写着「导出 JSON」，第二次迭代一检测就以为产物已有导出能力，于是永远跳过。现在判定前会先摘掉自己注入的样式与运行时块，并且以运行时块里声明的 `PLAN` 为准。
2. **被源码注释骗了**——模板注释里写「再改一版 → 加搜索/导出/柱状图」，正则分不出这是写给人看的还是真的能力。判定底稿现在会去掉注释。
3. **第 3 版的补丁被判成「已经注入过」**——早期用「有没有块」判重，导致第三版整块运行时被丢掉（徽标停在 v2、功能不出现）。改成每个版本块带自己的标记 `/*__forge_runtime_vN__*/`。

上面这套「这一版到底有没有某个能力」的判断，用户也看得见：输入框上方会列出**「下一步可以加」**的引导按钮，跟着当前预览这一版的实际能力变——已经挂过搜索框的版本不会再推荐搜索框，四项都齐了就如实说「这四项都齐了，直接说你想加的新东西就行」。它和打补丁共用 `analyzeEnhancements` / `capabilityHaystack` / `injectedFeatures` 同一套判定，所以**不会出现「推荐了却挂不上去」的按钮**；冒烟测试里有一条从首版一路照建议点下去的回路，断言四步正好补完四项、每一轮都真的生效、补完的产物依然可运行——推荐和注入只要哪天不一致，这条就会红。

### 3.3 产物跑在哪：沙箱 iframe，且刻意不给 `allow-same-origin`

生成的单文件 HTML 通过 `srcDoc` 注入 iframe，`sandbox` 里**故意不加 `allow-same-origin`**：产物拿到的是不透明源，碰不到主应用的 DOM、localStorage 和 Cookie。代价是沙箱内 `localStorage` 会抛 `SecurityError`，所以注入的运行时里带了一层内存版降级封装——产物的「存盘」在预览里照样能用。

同时注入一个探针：`window.onerror` / `unhandledrejection` 会 `postMessage` 回主应用，于是**产物里的报错能显示在工作台上**，而不是让你对着一个白屏猜。

### 3.4 自带 Key 这条路：Key 只在浏览器里，请求直连服务商

Key 只存在浏览器 `localStorage`，请求由浏览器**直连**服务商（所有服务商统一走 OpenAI 兼容协议，所以只需要换 `baseUrl`/`model`）。这条路**没有中转服务器**，也就没有「把用户 Key 抄到我们服务器」的可能。

### 3.5 托管模式：让 C 端访客零配置也能用到真模型

上一节那条路对评审很友好，对**普通访客**不友好：C 端用户不会为了试一句话先去注册一家模型服务商。默认的演示引擎虽然零配置，但它毕竟不是真模型。这个缺口只能用「站点方出钱」来填，而它**必须有一个服务端**——纯前端包里的任何 Key 打开 DevTools 就能看到。

于是有了 `server/hosted-core.mjs`：一个只做「转发 + 限流」的代理。三条硬约束写在了文件头的注释里：

1. **上游 Key 只存在服务端环境变量**里，不进浏览器、不进日志（日志逐处做 `[redacted]` 替换，部署时还会兜一层：万一上游把 Key 回显在报错体里也不会原样打出来）；
2. **模型名和 `max_tokens` 由服务端强制**，客户端传什么都不算——否则一次请求就能烧掉整天的预算；请求体按**白名单**取字段（`messages`/`stream`/`temperature`/`max_tokens`），上游网关将来多出什么危险参数也不会被顺手捎带过去；
3. **有配额**（按 IP + 全局每日），超了返回 429 并明确告诉访客「可以切回内置演示引擎」。

几个值得单独说的取舍：

- **平台无关**：核心只用 `Request`/`Response`/`fetch`/`ReadableStream`，所以同一份代码能跑在 Vercel Edge、Cloudflare Workers、Deno/Bun/Node 20+，各平台的入口只是几行 adapter。**本地测过的就是部署上去跑的**这一条，是靠 `npm run smoke:hosted` 起真的 HTTP 服务、打真的端口做到的。
- **超时的定义是「多久没开始回」，不是「总共多久」**：一拿到上游响应头就把定时器停掉。按总时长算的话，abort 信号会直接掐断 body 流，表现是「模型明明还在写，页面却停在中途被截断」，而且日志里只留一句超时——这个坑是实测踩出来的，注释里写清了为什么。
- **限流存在进程内存里**，多实例部署不共享，所以 `/api/health` 会**如实回报 `sharedLimits: false`**。这是一个「尽力而为」的限额，不是硬保证；要硬保证得接 KV/Redis，属于下一阶段（见 §5）。
- **前端怎么找到代理**：候选地址按可信度排序——手填 > 构建期 `VITE_HOSTED_BASE_URL` > 同源 `/api`。判定「代理可用」不能只看状态码：静态站对未知路径会回一张 **200 的 HTML 兜底页**，那会被误判成「代理可用」，访客点下去才发现每次生成都失败；所以还要求 `content-type` 是 JSON 且 `ok === true`。单文件版是 `file://` 打开的，那里**一个请求都不会发**（没有 http/https 就没有同源候选）。
- **唯一一处「替访客做决定」的地方被抽成了纯函数**（`decideHostedSwitch`）：探测到代理可用、访客从没手动选过引擎、当前是演示引擎 → 自动切过去（这就是零配置）；当前是托管模型但代理现在不可用（额度用完 / 站长撤了）→ 退回演示引擎。**访客一旦自己点过「设为当前引擎」，自动切换就永久失效**——而「退回」不看这条红线，因为它是修错，不是偏好。
- **额度用完时不再白打一次上游**：探测结论已经是「额度用完 / 站长没配 Key」时，流水线直接给出人话和退路（「切回内置演示引擎」在设置里），而不是先把请求打到代理上换一个 429 回来。

**代价**：这是整个项目里唯一的服务端组件，也是唯一会产生**真金白银账单**的地方（`HOSTED_DAILY_GLOBAL × 单次 token 上限` 就是每天的上限）。没部署它的站点上，「托管模型」这个选项不会被列出来——把一个点了必然失败的选项摆在访客面前，比没有这个功能更糟。

### 3.6 另一条零配置路：把 Key 打进前端包，以及它明码标价的代价

上一节说「纯前端包里的任何 Key 打开 DevTools 就能看到」——这句话是对的，但它推出的是**「不要把 Key 放进前端」**，不是**「零配置必须有个服务端」**。这两件事得分开：如果目标只是「评审点开链接就能用上真模型」，那把一个**本来就是给这个演示用、随时可以作废的** Key 打进包里，是比多部署一个组件更简单、也更不容易坏的做法。

`src/lib/station.ts` 就是这条路的全部：构建期读 `VITE_STATION_API_KEY` / `VITE_STATION_BASE_URL` / `VITE_STATION_MODEL`，有 Key 就多出一个「本站内置模型」引擎（`STATION_PROVIDER`）。

几个刻意的选择：

- **它是独立的一个 provider，不复用托管模式那一项**。托管那张卡片上写着「上游密钥只存在服务端，浏览器里拿不到」——那句话对内置 Key 是假的。共用一个 provider 就意味着界面上要对访客说一句谎，所以宁可多一个 id、多一段文案，界面上写着：*「这个 Key 是打包进网页的，懂技术的人查看页面源码就能找到它（这是"开箱即用"的代价）。请不要用它处理机密或敏感数据。」*
- **没配 Key 就整项不出现**（`stationAvailable()`），跟托管模式的规矩一致：不把一个点了必然失败的选项摆在访客面前。
- **它在代码里一个字都不出现**，只从构建期注入。仓库和历史保持干净，想撤就把那个 Secret 删掉、重新构建一次（`decideStationSwitch` 的 `fallback` 分支会让正在用它的访客退回演示引擎并说明原因，不需要访客做任何事）。
- **一旦访客自己选过引擎，自动切换就永久失效**——和托管模式共用同一条红线（`providerChosen`），而「Key 被撤了要退回」不看这条红线，因为它是修错，不是偏好。这条策略被抽成纯函数 `decideStationSwitch`，13 条断言钉着它，包括「已经自带 Key 的访客不会被拽走」。
- **`providerChoices(includeHosted, includeStation)` 两个开关分开传**，谁配了谁才出现，测试里可以单独模拟四种组合。

这条路的**唯一真实风险是钱**：没有配额、没有上限，只有你了不了解自己的 Key 放在公开网页上意味着什么。所以 §2 里那条优先级是「先走有护栏的 C，再走没护栏的 D」，以及 §0 里那段警告——被跟踪的 `forge-standalone.html` 永远不含这个 Key。

### 3.7 一次生成 + 一次自动修复

模型偶尔会漏掉一个闭合标签或者引一个 CDN。产出后先做静态自检（可运行性、外部依赖、脚本可解析），不通过就把**具体原因**回灌给模型重试一次；再不过就如实告诉你哪里不行。自动修复过的版本会打上标记。

### 3.8 不引入依赖：手写 CSS + 极小的状态层

没有 UI 库、没有 CSS 框架、没有 react-router、没有 Redux/Zustand。状态层是 40 行的 `useSyncExternalStore` + 模块级 store；路由是 `#/`、`#/p/<id>`、`#/s/<code>` 的 hash 路由；样式是手写的 CSS 变量主题。

**取舍**：写起来慢一点，换来的是**构建产物 257KB（gzip 88KB）**、没有版本地狱、也没有「安装依赖失败」这种在评审机器上很致命的意外。另外把资源路径设成相对的（`./assets/...`），于是**部署到子路径（比如 GitHub Pages 的 `/repo/`）也不会白屏**——这条不是嘴上说说：`npm run smoke:dist` 会把打包产物拷到一个嵌套子目录里，用无头 Chromium 真的打开，断言 JS 包真的挂载出了界面、CSS 包的样式真的作用到了元素上（查 computed style，不是只看文件在不在）。

### 3.9 分享：没有后端，那就把整个应用塞进链接里

`share.ts` 用 `CompressionStream('deflate-raw')` + base64url 把整个项目压进 URL 片段（`#/s/<code>`），并保留一个未压缩的兜底前缀（老浏览器走 `'0'` 前缀）。实测 **23479B 的产物 → 5021B 的分享码（21.4%）**。

**取舍**：链接会很长，但它不依赖任何服务器、不会过期、也不会把别人的作品存到我们的数据库里。「打开别人的分享链接」这条路径零配置可验证，对评审很友好。

### 3.10 单文件版：一个"内联而已"的需求，踩了三个静默坑

「把产物内联成一个 HTML」听起来是十行代码，但做的时候连续踩了三个**不报错、只是白屏**的坑，值得记一笔：

1. **`</script` 会提前闭合脚本元素**。压缩产物里本来的 `</script` 已经被 Vite 转义成 `<\/script`，但仍然逐处兜一层（`<\/script` 在字符串、模板、正则里都语义等价）。
2. **`<!--` 会把 HTML 分词器带进 "script data escaped" 状态**。进了这个状态之后，脚本里后面出现的 `<script` 又把它推进 "double escaped"，而只有字面量 `</script` 才能退回来——产物里恰好**一个都没有**（全被第 1 条转义了），于是永远退不出来，脚本元素一直不闭合，浏览器把 `</body></html>` 全当成脚本体吃掉，报 `Unexpected token '<'` + `Unexpected end of input`。触发它的是我自己代码里的一个正则（`enhance.ts` 里去 HTML 注释用的 `/<!--[\s\S]*?-->/`）；改成 `<\x21--`（`\x21` 就是 `!`，在字符串/模板/正则里都等价，且不像 `\!` 那样在 `u` 模式正则里报错）就绕开了。
3. **`String.replace` 的 `$&` 替换模式**。用字符串做替换内容时，`$&` 会被替换成"匹配到的整段"，而压缩后的 JS 里正好有 3 个 `$&`——第一版就这样把 `<script src="...">` 这个标签原样插进了 JS 三处。页面照样能生成、但内容是坏的，属于最难发现的那类 bug。**所有插入负载的替换都必须用函数形式**，并加了"内联内容必须与产物逐字节相同"的断言把它钉死。

最后一条同样来自实测而不是推理：**`file://` 下 `localStorage` 到底能不能用**（任务要求持久化，而单文件版的运行前提就是 `file://`）。验证脚本在**不加任何命令行开关**的条件下从 `file://` 打开它，真的点一次示例、点一次「生成」，再断言产物挂进了沙箱 iframe、`forge:projects` 真的落盘了——和用户双击打开时的条件完全一致。

还有一个**只有带 Key 构建时才会暴露**的坑：验证脚本原来会自动走完主流程，而带 `VITE_STATION_API_KEY` 构建出来的包里，App 开机就会自动切到「本站内置模型」——于是跑一次单文件验证＝一次真实、缓慢、要花钱的上游调用（CI 每次构建都会跑它）。修法是在 PROBE 的最前面用一段**同步的**经典脚本把 `localStorage` 里的设置钉死成「内置演示引擎 + `providerChosen: true`」，它在被 defer 的 `<script type="module">` 之前执行，所以 App 起来时看到的已经是这个状态。这段注释在 `scripts/standalone.ts` 里写清楚了，免得以后有人看到「为什么冒烟测试要偷偷写 localStorage」而删掉它。

## 7. 隐私

三条路要分开说，因为它们的信任模型不一样。

**两条本地路径（内置演示引擎 / 自带 Key）**：Key 只存在你这个浏览器的 `localStorage`，**请求从浏览器直连服务商**，中间没有任何我们的服务器。演示引擎和四个迭代补丁全部在本地跑，不联网。

**站点内置的那条（§3.6）**：请求同样**从你的浏览器直连上游服务商**，不经过我们的服务器，我们也因此看不到你输入了什么。但它跟「自带 Key」有一个本质区别，必须说明白：**那个 Key 是公开的**，它就在页面源码里，任何人（包括你）都能拿到它，也都能拿它去调用上游、花站点方的钱。所以站点方会把它当成一个可作废的演示用 Key；**请不要用它处理机密或敏感数据**——这不是提醒你注意隐私，是提示你这把钥匙不只一把。介意的话，用「自带 Key」那条，或者用演示引擎。

**站点托管这条路**：请求**会经过本站自己的代理**（见 3.5），这是「访客零配置」又「Key 不公开」的唯一组合。代理的边界是刻意画窄的：

- 上游 Key 只在服务端环境变量里，**不进浏览器、不进日志**（日志逐处 `[redacted]`，并且部署时会把上游回显的 Key 也从报错体里抹掉）；
- 代理**不存**你的提示词、不存产物、不存任何用户数据；唯一留下的东西是**每日请求计数**，而且只在进程内存里（进程重启就归零，`/api/health` 会如实回报 `sharedLimits: false`）；
- 计数用 IP 只是为了限流，不落库、不关联身份、不用于别的任何用途。**介意的话就切回自带 Key**——那时请求不经过我们，这一点在设置里和这里都写明了。

用真模型的三条路（自带 Key / 站点托管 / 站点内置）里，**你的提示词都会发给上游模型服务商**——这跟前端无关，是"用真模型"的固有代价，选哪条路都避不掉。不想让任何内容离开浏览器，就只能用内置演示引擎，它不联网。
